# 交付前门禁（Pre-flight Checklist）

> 来源：taste-skill 的 pre-flight 机制 + 受控实验全部发现。
> 规则：交付任何页面/组件前逐条过。**任何一条不过就不交付**，修完再查一遍。

## 第 0 步 · 用户偏好账本（最高优先级）

- [ ] 已读取 `references/user-preferences.md`，逐条对照所有生效规则
- [ ] 本次会话中用户新给的反馈已按自进化机制入库，且已用新规则复查本次全部产物
- [ ] 自己在截图、浏览器验收、回传测试、lint/test/build 或真实交互里发现的可复现问题，
      已自动写入设计记忆并同步为规范/门禁；当前产物已复查修正

## A. 反套路扫描（AI Tells）

- [ ] 无紫蓝渐变、无 `#000000` 纯黑、无外发光霓虹、无大标题渐变文字
- [ ] 字体不是 Inter/Roboto/Arial/系统默认，且和上次生成不同
- [ ] **全页无 `font-style: italic`**（中文伪斜体尤其禁止；强调只用字重/颜色/字号）
- [ ] Hero 不是居中构图（除非设计读取明确要求）
- [ ] 无三等分卡片横排；卡片没有被当作万能分组容器
- [ ] 无 John Doe/张三、无 99.99% 式整数假数据、无 Acme 式烂梗名
- [ ] 文案无"革命性/颠覆/无缝/赋能/下一代"；感叹号 ≤ 1
- [ ] 眉批（eyebrow）数量 ≤ ⌈section 数 / 3⌉；无 "SECTION 01" 式编号 meta-label
- [ ] H1 不超过 2-3 行（窄容器多行大标题 = 失败）
- [ ] Bento/网格无空洞（`grid-auto-flow: dense`，span 完全咬合）
- [ ] 无左侧竖线装饰（border-left 色条 / inset 竖条）用于选中或卡片强调（P-38）
- [ ] 图表/统计卡的时间窗口文案与查询用的常量同源，没有手写的窗口数字（P-55）
- [ ] 视图/模块只有一个名字：入口、标题、组件名、CSS 前缀、文档章节名同源（P-69）
- [ ] **参考没有被当成目标值**：参考只用于校准工艺基准，方案里「参考给的基准」与「我们的取舍（含理由）」两列分开；把参考截图拿走后，身份层的每个决定（色温 / 字族分工 / 材质 / 强调色 / 记忆点）仍有自己的理由（P-87）

## A2. 进攻三步核验（craft-loop.md）

- [ ] DNA 注入：能逐条说出"从 {site} 的 DESIGN.md 偷了哪 3-5 个具体值"
- [ ] 工艺密度：签名动作 ≥ 5 项，可逐项指认位置
- [ ] 两轮制：第一轮截图 + 四视角评审记录（各至少一处）+ 第二轮修复均已发生

## A3. 资产与可读性（assets-and-readability.md）

- [ ] Hero 视觉侧过关：图像生成资产 / 高保真组件预览（深度≥3层、元素≥8、有活细节、
      构图有姿态）/ 抽象编辑构图，三选一——无空心 div 假截图、无"文字+渐变斑点"
- [ ] 暗底正文 `rgba(255,255,255,.85)`、次要文字 ≥ `.60`；正文区纹理 ≤ 3%
- [ ] 每个 CTA 做过对比度审计；主 CTA 不换行；同一意图全页一个文案
- [ ] 文案自审完成：无语法不通/指代不明/AI 装深沉句；假精确数据已清理
- [ ] 正式多方向展示（非 Phase 2 风格试衣间）：每方向全宽沉浸带 + 独立工艺密度 ≥ 3 + 设计宣言入版面

## A4. 功能契约（任何 VARIANCE 值都不豁免）

- [ ] 已写下本页功能契约（存在理由 / 3 秒必得信息 / 必须能完成的动作）并逐条核对
- [ ] 页面类型的核心标识首屏可辨（404 的错误码、定价的价格、表单的提交路径）
- [ ] 创意元素没有遮蔽或稀释任何契约项
- [ ] 既有页面重设计：原来的信息性视图（图表 / 日历 / 时间线）仍在，并说清每一块是「保留重画」还是「有别的通道接手」；要删的已单独提出并获确认（P-68）

## A4.1 Carbon 决策门（功能型 UI / 仪表盘 / 表单 / AI 工具必查）

- [ ] 对关键组件已回答“何时用”和“为什么不用邻近组件”，没有只因为好看选型
- [ ] 新增/重做的关键组件已定义 anatomy、content、states、keyboard、narrow viewport、overflow 和 recovery
- [ ] 主工作流已覆盖 entry / progress / result / exception / recovery / exit，不是只画 happy path
- [ ] loading 选择与任务匹配：结构预览=skeleton，未知等待=indicator，已知进度=progress，已有内容刷新不清空
- [ ] empty / no results / unavailable / permission / error 已区分，每个状态有具体下一步
- [ ] disabled / read-only / hidden 语义没有混淆，禁用原因和解锁路径可理解
- [ ] tooltip 未承载完成任务必需信息；含交互的补充内容使用 toggletip/popover/dialog 并管理焦点
- [ ] 展开/切换/tab/评分/预览等状态按实例独立管理，没有一个全局布尔值带动所有组件
- [ ] 有分享、回退、重载价值的 tab / 筛选 / 搜索 / 分页状态已进入 URL
- [ ] 项目品牌与现有组件库仍为主；没有因引用 Carbon 方法就复制 IBM 蓝、Plex 或 Carbon 默认外观

## A4.2 数据可视化门（有图表时必查）

- [ ] 每张图先写了用户问题，图表类型与比较/趋势/占比/相关/连接/空间任务匹配
- [ ] 轴、基线、单位、时间范围、缺失值和数据来源明确，没有用截断轴夸大差异
- [ ] 颜色是在编码类别/顺序/正负/状态，不是装饰；不看颜色仍能理解
- [ ] 聚合量与曲线同量纲：被缓存/重读/历史平均主导的量不单独当用量画，lifetime 平均不冒充实时指标（P-60）
- [ ] 图例、tooltip、筛选和下钻支持键盘；关键数据有文本摘要与表格/导出等价形式
- [ ] 已测试极值、负值、全 0、单点、缺失、长标签、多系列、无数据和窄屏

## A5. 方案预览交付门（Phase 2 必查）

- [ ] 如果用户要求设计方案、重构方案、多个方向或风格建议，已生成可打开的浅层预览目录 `design-previews/YYYY-MM-DD-任务名/index.html`
- [ ] 若用户追问没有预览、要求看预览或强调四种方向，当前回合已立即补交四方向预览页；没有只解释流程、只道歉或再次要求确认
- [ ] `index.html` 是自包含 HTML，并通过 HTML 解析或等价结构检查
- [ ] 预览目录非隐藏、层级不超过 `design-previews/<date-task>/`；用户可直接找到、打包、分享
- [ ] 预览页用低干扰单句说明"这是设计方向样机 / 不是最终 App 或最终页面 / 选择后才进入正式实现"
- [ ] 预览页包含至少 4 个真实 mini mockup，且差异覆盖布局、密度、色彩或字体中的多个轴，不只是换颜色
- [ ] 四方向是 A/B/C/D 硬下限；未被三套文字方案、两种风格建议或推荐方向说明替代
- [ ] 多方向已按 subagent 或独立 brief 隔离生成；若无法使用 subagent，已说明降级原因
- [ ] 每个方向使用独立 stage 与 scoped CSS / 独立类名前缀，无全局样式污染其它方向
- [ ] 桌面和移动端截图都已检查：页面无横向滚动，mini mockup 占满或居中，内部文字/控件没有互相挤压或遮挡
- [ ] 设计样机区和方向说明区已分离；主视觉区域只放 mockup、短标签和选择按钮，不混入长解释、参数表或评审说明
- [ ] 按钮上方若有方向短说明，必须横排可读、full-width、最多两行；没有一字一行、竖排、窄栏挤压或被按钮遮挡
- [ ] 四方向预览在桌面端默认是 2×2 左右两栏网格，移动端是单列；若使用全宽沉浸展示，已写清必要性
- [ ] 预览页遵守奥卡姆剃刀：无重复说明、小字教程、长段免责声明或系统自言自语
- [ ] 其中一个方向明确标注「推荐」，并在页面和回复中说明推荐理由
- [ ] 已启动本地预览回传服务并自动打开浏览器，或明确说明服务无法启动的降级原因
- [ ] 每次重启预览服务后已明确告知新的本地 URL；旧端口页面视为过期缓存，不作为验收证据
- [ ] 预览页外侧选择 UI 保持统一：固定顶部状态栏、快捷键提示、统一选中高亮与回传 toast
- [ ] 选择按钮已有"选择 A/B/C/D · 方向名"文案时，顶部或卡片上方没有重复"点按钮选择"说明
- [ ] 每个方向卡片都有明显的选择按钮，按钮文本包含方向字母和方向名
- [ ] 运行本地预览服务后，每个方向只有一组选择按钮；HTML 自带按钮已用 `.qmdp-pick-button`
      或等价标识避免服务重复注入
- [ ] HTML 自带选择按钮已有自己的回传处理时，预览服务不会再次处理同一次点击；服务自动注入按钮必须带
      `data-qmdp-injected` 或等价标识
- [ ] 页面自带 `.qmdp-pick-button` 但没有自己的回传处理时，点击按钮会由预览服务接管并打开确认弹层；
      只有显式标记 `data-qmdp-native-handler="true"` 或 `data-qmdp-managed="page"` 时才跳过服务处理
- [ ] 重复按钮检查基于服务注入后的真实 DOM / 截图，而不只是源码 grep；嵌套在 `.meta`
      等内部容器的按钮也必须被服务识别
- [ ] 对用户展示三拨盘时使用中文标签和解释，说明用户可调整；没有只显示
      `VARIANCE/MOTION/DENSITY` 英文参数名
- [ ] 三拨盘在预览页中是可拖动滑块，拖动时当前数值即时可见变化；确认选择时 `dials` 随方向一起回传
- [ ] 点选方向、按钮或键盘 1-4 只打开确认弹层；弹层包含方向名、当前拨盘值和调整建议输入框
- [ ] 只有用户点击"确认并回传"后才写入选择；页面无 60 秒倒计时、超时默认选择或推荐态自动写入
- [ ] 预览服务提供 `POST /api/select` 与 `GET /api/selection`，选择会写入预览目录内的 `selection.json`
- [ ] `selection.json` 包含 `id/name/label`，并保留 `dials` 与 `adjustments` 字段
- [ ] 用户可见的回传文案只说"已回传"或"当前未能回传"，没有绑定具体工具名或调用端
- [ ] watcher 优先使用文件事件、服务日志哨兵或 `--exit-on-select` 快速路径；短轮询兜底间隔不超过 75ms
- [ ] 执行代理进入 Phase 3 前已观察到 `selection.json` 或 `QIAOMU_DESIGN_SELECTION::` 日志，或用户在对话中明确选择/授权默认
- [ ] 启动预览后没有发送 final 结束回合；已保持 watcher/轮询，直到选择被消费或用户明确说稍后再选
- [ ] 最终回复给出可点击的本地文件路径和本地预览 URL；缺少路径不得交付
- [ ] 若因权限或项目约束无法写文件，已明确说明阻塞原因，并提供完整可保存 HTML 内容作为替代

## A6. 乔木身份边界

- [ ] 除非用户明确要求，生成页面没有默认添加打赏二维码、公众号关注、GitHub/X 浮条、乔木推荐入口或个人 Profile 区块
- [ ] 对外分享页面如需署名，最多使用低干扰页脚 `Powered by 向阳乔木` 链接到 `https://qiaomu.ai/`

## A6.1 代码阅读面门禁（reader / diff，P-64~67）

- [ ] diff 两侧分色：旧侧删=红、新侧增=绿；没有一条规则同时套两侧（旧侧被删的行画成绿 = 语义错误，P-67）
- [ ] 改动的信号齐全：行号（并排模式下同时是折叠开关）、行底 wash、字符级高亮（**仅当改动短于整行**；整行改动只留 wash，见 P-73）；单栏保留变更条；文字保持 ink，只有 `+/-` 记号本身染色
- [ ] 并排模式无 gutter 变更条；未改动区收起/展开两态都有行号列里的折叠开关，且两侧折叠集合一致（P-73）
- [ ] 行底 wash 与字符高亮是两个档位（本项目 10% / 24%），不是同一种颜色叠两层
- [ ] 折叠未改动区是一条安静的 rule（发丝线 + 纸色带 + hover 变 ink），且库自带的装饰字形已关掉
- [ ] 选区在 diff 里可见（`drawSelection()` + theme 里那三条 `::selection`），与 reader 同一枚 wash
- [ ] CodeMirror 皮肤全部写在 `EditorView.theme()`（P-66），并用 `StyleModule.getRules()` 核过没有死选择器
- [ ] 盖库自己的 `background` 简写时重声明的是 `background` 而不是 `background-color`（否则它的 `background-image`（如 2px 下划线）会留在底下），且选择器比库的多带一个 class（P-67）
- [ ] reader 与 diff 的代码节奏同源：字号、行高（`--explorer-line-height`）、gutter 底色、等宽字体

## B. 设计读取一致性

- [ ] 产出与声明的设计读取、三拨盘值一致（说了 VARIANCE 9 就不能交居中对称）
- [ ] 全页主题锁定：一页只有一个明暗主题，不混
- [ ] 新增块的内容对齐到应用既有内容列（本项目 `clamp(560px, 46vw, 760px)`），没有无理由的满宽撑满；浮层归 composer 浮层族（`bottom: calc(100% + 8px)` + `width: 60%` + 同 clamp + 白卡全边框）；行内 gutter 用列内边距而不是负偏移（P-57）
- [ ] 浮层与 chrome（窗框 / 页头 / 工具条）之间留 8px gutter，与它所覆盖的内容之间不留（P-62）
- [ ] 浮层内部按语义分行（控件行 / 上下文行 / 遥测行），行内可截断的长文本项没有用 `flex: 1`（basis 0 永不换行，只会被压成省略号）；浮层结构随自身宽度自适应，不用视口断点（P-75）
- [ ] 改卡片 / 面板内部间距前，已确认那个容器的**直接子元素**就是这些行（闭合标签位置，不是缩进）——容器只剩一个子元素时 `gap` 等于没写（P-78）
- [ ] 可展开面板只装「能改的设置」：只读数据留在详情弹窗 / 专属页面 / 仪表盘；搬任何数据上来之前已过三关（会变 × 会改变当下动作 × 不会自己冒出来）并查过它现在有几个入口（P-76）
- [ ] per-partner 的设置与指标按**频率**分家：高频的 model·effort 在输入药丸里的 chip（就地改），低频的 sandbox 与全部指标在 partner 自己的详情页（header 点名字 / ⌘E）；没有用「去仪表盘看」回答单个 partner 的指标问题（仪表盘只管全景横向比较，P-77）
- [ ] per-partner 的设置 RPC 都带 `name`（按 partner 寻址），不隐式作用于「当前选中」的 partner（P-77）
- [ ] 面板 / 脚注里的速率、延迟、token 数写清了窗口（本次会话累计 / 均值），没有与「正在运行」同排冒充实时（P-60 / P-76）
- [ ] pin 住的详情隐藏所有关闭该文件/详情的可见出口（面板 `×`、头部 `← 返回`），只留 pin 按钮；Esc 仍可作为逃生口并逐层关闭（P-61）
- [ ] 能一句话说出这一页的**记忆点**是什么
- [ ] 动效气质与视觉气质一致（cohesion）

## C. 动效抽查（详表见 motion-craft.md）

- [ ] 动效有明确目的和频率判断；高频/键盘触发操作没有动画
- [ ] 无 `transition: all`；无 UI `ease-in`；无 `scale(0)` 或纯 fade 入场
- [ ] UI 动效 ≤ 300ms；按压有 `:active` 反馈
- [ ] popover/dropdown/tooltip 从触发源 origin 出现；modal 才保持 center
- [ ] `prefers-reduced-motion` 兜底存在
- [ ] hover 动效包在 `@media (hover: hover) and (pointer: fine)` 内
- [ ] 只动了 transform/opacity；没有动画 `width/height/margin/padding/top/left`
- [ ] 入场/过渡位移用的是独立的 `translate` / `scale`（不是 `transform`），没有顶掉元素定位用的 `transform: translateX(-50%)` 之类；写完 grep 过目标元素是否也有 `transform:`（P-79）
- [ ] 快速触发组件用 transition 或 spring，不用重播 keyframes
- [ ] 收起/展开的容器做过往返测试（收起再展开）：内部 state（展开的树、滚动位置、输入内容）不重置；收起靠 class + 过渡，不靠卸载
- [ ] 手势/拖拽/sheet/swipe：pointer-down 即时反馈、1:1 跟手、pointer capture、velocity handoff、
      rubber-band 边界、可中断；已读 `apple-fluid-interfaces.md`
- [ ] Framer Motion / Motion 高负载场景没有用 `x/y/scale` shorthand 造成主线程掉帧风险
- [ ] Esc 只有一个消费者（useKeybindings 的 Esc 行为）；每个可被 Esc 关闭的层都登记在 ESCAPE_ORDER，没有新增全局 keydown 监听（P-63）
- [ ] 读 `defaultPrevented` 之前没有任何 `preventDefault`（含 keybindings 自身的默认阻止顺序）：handler 先跑、读完 flag 再阻止默认（P-63）
- [ ] 覆盖第三方自带的 `!important` 规则：选择器要比对方多一个 class（`!important` 之间先比特异性、再比顺序），不要指望挂载顺序（P-66）
- [ ] 给第三方编辑器/组件写样式时，优先用它文档给出的选择器形状（自拼 DOM 路径常见是死选择器）；写完用 style-mod `getRules()` 验一遍（P-66）
- [ ] 需要让某个子树不继承全局视觉规则时，优先把颜色/值**间接化成变量**在该子树覆写，而不是靠选择器特异性对抗（P-66）
- [ ] CodeMirror theme 的 key 是**相对根元素**的：根上的条件必须写 `&`（`&.cm-focused`），写裸 `.cm-editor` 会变成“要求它是根的后代”而永不匹配（写完用 style-mod `getRules()` 核一遍）（P-66）
- [ ] CodeMirror 皮肤写在 `EditorView.theme()`（CM6 运行时注入的 base theme 会赢等特异性的 style.css 规则）；style.css 只留外壳（P-66）
- [ ] 结构（折叠 / 缩进 / 括号）来自 parser；没有 parser 时宁可不提供，不用正则 / 括号计数近似（P-65）
- [ ] 代码色彩只有 shiki 一个来源；若引入 lezer，只取结构（折叠 / 缩进 / 括号），不装 `syntaxHighlighting`（P-64）
- [ ] 内层消费 Esc 时用 preventDefault 标 handled；中央 handler 遇 defaultPrevented 让位（P-63）
